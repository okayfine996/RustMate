# Feature Specification: 菜单栏工具链切换

**Feature Branch**: `003-menu-bar-toolchain`  
**Created**: 2026-01-01  
**Status**: Draft  
**Input**: User description: "为这个app实现一个菜单栏常驻功能，菜单栏显示当前的工具链版本，然后支持工具链版本切换以及唤起app主界面功能。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 菜单栏显示当前全局工具链 (Priority: P1)

作为 RustMate 用户，我希望在 macOS 菜单栏能直接看到当前“全局默认”工具链标识，这样我无需打开主界面也能确认当前正在使用的默认工具链。

**Why this priority**: 这是该 App 的核心价值（切换全局 toolchain）的前置条件：用户必须先能“看见当前状态”。

**Independent Test**: 启动 App 后，检查菜单栏是否常驻显示当前全局默认工具链标识，并且在状态不可用时有可行动的提示。

**Acceptance Scenarios**:

1. **Given** App 已启动且处于常驻状态，**When** 用户查看菜单栏图标/标题，**Then** 菜单栏应显示当前全局默认工具链标识（例如通道名或版本标识，具体以系统返回的“工具链标识”字符串为准）。
2. **Given** App 无法获取当前全局默认工具链状态（例如环境异常），**When** 用户打开菜单栏菜单，**Then** 系统应以用户可理解的方式展示“无法获取当前工具链”的原因，并提供至少一个可行动选项（例如重试或打开主界面查看诊断）。

---

### User Story 2 - 从菜单栏切换全局默认工具链 (Priority: P1)

作为 RustMate 用户，我希望从菜单栏直接选择并切换全局默认工具链，这样我可以在不离开当前工作的情况下快速切换编译环境。

**Why this priority**: “切换全局 toolchain”是 App 的核心任务，菜单栏是最快入口。

**Independent Test**: 通过菜单栏菜单选择一个不同的工具链标识，观察系统默认工具链是否变更、菜单栏显示是否同步更新、失败时是否给出清晰提示与下一步建议。

**Acceptance Scenarios**:

1. **Given** 系统存在多个可用工具链标识，且当前工具链为 A，**When** 用户在菜单栏选择工具链 B，**Then** 系统应将“全局默认工具链”切换为 B，并在操作完成后更新菜单栏显示为 B。
2. **Given** 用户发起切换后发生失败（例如目标工具链不可用或系统拒绝），**When** 操作结束，**Then** 系统应清晰展示失败结果（含原因与建议动作），并保持菜单栏显示仍为原工具链 A（或明确标注切换未生效）。
3. **Given** 用户在切换进行中再次尝试切换，**When** 用户触发第二次切换，**Then** 系统应避免产生不可预测状态（例如明确提示“正在切换中”，或采取一致的排队/取消策略并对用户可见）。

---

### User Story 3 - 从菜单栏唤起 App 主界面 (Priority: P2)

作为 RustMate 用户，我希望能从菜单栏一键打开/切回 RustMate 主界面，这样我可以在需要更详细信息或设置时快速进入主界面。

**Why this priority**: 菜单栏承担“快捷入口”，主界面承担“详细信息与设置”；二者必须无缝跳转。

**Independent Test**: 在主界面关闭/后台时，从菜单栏点击“打开 RustMate”，验证窗口被唤起并置前。

**Acceptance Scenarios**:

1. **Given** App 正在运行但主界面不在前台，**When** 用户在菜单栏选择“打开 RustMate”，**Then** 主界面应被唤起并置于前台（可交互）。

### Edge Cases

- 菜单栏图标/标题区域显示空间不足时，应有降级策略（例如仅显示图标或使用更短的工具链标识）。
- 系统无法枚举可用工具链列表时，菜单栏应提供重试与“打开主界面查看原因”的路径。
- 可用工具链列表为空时，应明确提示并引导用户到主界面完成安装/修复（不要求菜单栏内完成该工作）。
- 切换过程中 App 被退出或崩溃时，重启后应能恢复到“展示当前全局工具链”的一致状态。
- 当存在“项目级工具链覆盖”（例如项目配置覆盖全局默认）时，菜单栏仍以“全局默认工具链”为展示对象，并在用户可能产生误解时提供提示文案（例如在主界面中解释覆盖规则）。

## Requirements *(mandatory)*

### Constitution Constraints (mandatory)

- **No-default-XPC**: 本功能默认在主 App 进程内完成，不要求 XPC 作为前置条件；如后续引入，需在计划中说明明确收益与替代方案对比。
- **Sandbox & Security**: 菜单栏触发的任何“切换工具链”动作不得将未验证输入作为系统执行参数；权限请求遵循最小权限原则；出现权限/环境问题时应提供可理解且可行动的提示。
- **Structured Results**: 菜单栏与主界面呈现的结果必须以结构化状态/错误为主（成功/失败/原因/建议动作），不依赖原始多行输出文本作为核心协议。

### Functional Requirements

- **FR-001**: 系统 MUST 提供一个可见的“菜单栏常驻入口”，用户无需打开主界面即可访问核心操作。
- **FR-002**: 系统 MUST 在菜单栏中展示“当前全局默认工具链标识”（当空间不足时允许降级为仅在菜单内展示，但必须可被用户找到）。
- **FR-003**: 系统 MUST 在菜单栏菜单中提供“可用工具链标识”的选择列表，供用户发起切换。
- **FR-004**: 用户 MUST 能通过菜单栏将“全局默认工具链”切换为所选工具链，并在完成后看到菜单栏显示同步更新。
- **FR-005**: 系统 MUST 提供“打开 RustMate 主界面”的菜单项，并能将主界面唤起到前台。
- **FR-006**: 系统 MUST 在“无法获取状态/无法切换”等失败情况下提供清晰的错误信息与至少一种可行动的下一步（例如重试、打开主界面查看诊断）。
- **FR-007**: 系统 MUST 在切换执行期间提供明确的进行中状态，且不得导致 UI 无响应（用户应能判断是否正在切换与是否已完成）。
- **FR-008**: 系统 MUST 避免并发/重复切换导致的不一致状态，并对用户可见地处理（提示、排队或取消策略必须一致且可理解）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: App 启动后，用户在 2 秒内可在菜单栏（或菜单内显著位置）看到“当前全局默认工具链标识”。
- **SC-002**: 在系统环境正常且目标工具链可用时，95% 的切换操作在 10 秒内完成，并在完成后 1 秒内刷新菜单栏显示。
- **SC-003**: 90% 的用户可在不打开主界面的情况下完成“查看当前工具链 + 切换到另一工具链”的主任务（不需要额外引导）。
- **SC-004**: 菜单栏完成一次切换的交互步骤不超过 2 次关键点击（打开菜单 + 选择目标）。
