# Research: 玻璃拟态 UI 视觉升级（对齐参考风格）

**Feature**: `004-glass-ui-refresh`  
**Date**: 2026-01-02  
**Goal**: 在不破坏现有 IA/功能的前提下，对齐参考截图风格（暗色、卡片化、胶囊筛选、克制玻璃拟态），并确保可读性/可访问性优先。

## Decision 1: 玻璃拟态的使用边界

- **Decision**: 玻璃拟态仅用于“容器层级”和“浮层/弹窗”强调，不覆盖整屏背景；列表行/主内容保持高对比的实色/轻微透明。
- **Rationale**: 全屏大面积 blur/material 容易造成对比不足与 GPU 压力；并且在浅色模式更易“糊掉”。
- **Alternatives considered**:
  - A) 全屏玻璃底：更“炫”，但可读性与性能风险高
  - B) 完全扁平：稳但缺少参考风格的质感层次

## Decision 2: 设计 tokens（统一尺度）

- **Decision**: 建立一套跨页面 tokens（颜色、间距、圆角、描边、阴影/高光、字体层级），并要求所有新增 UI 组件只使用 tokens。
- **Rationale**: 视觉升级的最大风险是“每个页面各自调参”导致不一致；tokens 是控制范围与一致性的唯一手段。
- **Alternatives considered**:
  - A) 每页局部调整：短期快，但一致性不可控
  - B) 先做 tokens 再落地：稍慢，但长期收益高（选择此方案）

## Decision 3: 状态体系（结构化 + 可行动）

- **Decision**: 对 loading / running / success / failed / empty 统一组件模式：状态图标/徽标 + 一句摘要 + 1~2 个动作（重试/打开设置/复制）。
- **Rationale**: 现有项目宪章强调结构化结果；UI 不应以长文本为主来解释失败。
- **Alternatives considered**:
  - A) 展开 stderr 长文本：排障方便但破坏界面简洁
  - B) 仅 toast：信息太少，用户不可恢复

## Decision 4: 对比度与可访问性优先级

- **Decision**: 可读性优先于“更像玻璃”的效果；浅/深色都必须保持标题/主按钮/关键状态高对比；键盘焦点必须可见。
- **Rationale**: 玻璃拟态最常见失败点就是对比度不足与焦点不明显，直接影响可用性与专业感。
- **Alternatives considered**:
  - A) 更强的透明与高光：更“玻璃”，但对比度更难控
  - B) 更克制的透明：更稳（选择此方案）

## Decision 5: 层级与信息密度（对齐参考截图）

- **Decision**: Toolchains 首屏采用“标题 + 摘要 + 概览卡片（3 个）+ 主列表”的层级；列表条目采用“左侧符号/状态条 + 中部信息 + 右侧主操作”的结构。
- **Rationale**: 参考截图的核心价值是“信息一眼能扫到”，并且主操作明显。
- **Alternatives considered**:
  - A) 全列表：密度高但层级弱
  - B) 过多卡片：层级强但首屏信息溢出（控制在 2~3 张概览卡）

## Open Questions

本特性无必须澄清项（不引入新行为/新权限/新数据）；所有决策以“可读性与一致性优先”为默认准则。
